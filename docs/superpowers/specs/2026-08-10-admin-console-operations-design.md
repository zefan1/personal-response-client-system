# 管理后台运营界面改造设计

## 目标

让管理员第一次打开后台时能明确知道下一步操作，并在桌面和窄屏下完成测试、表格连接、客户查看、模板发布、分组账号管理、规则配置和漏斗分析。

## 已确认的产品规则

- 一个业务组只有一名组长。
- 一个成员只能属于一个业务组。
- 账号列表按组分段展示：组头显示组名、组长和成员数，组内先显示组长再显示组员，未分组账号单独展示。
- 模板名称统一称为“模板标题”；线索类型使用下拉选项；模板发布范围支持全部成员或指定一个或多个组。
- MariaDB 仍是客户主数据来源；Smart Sheet 是投影/配置连接，不改变客户数据权威关系。

## 交互与视觉方案

1. 在线测试采用“选择能力、输入内容、执行并看结果”的三段式流程，空状态直接提供选择入口。
2. 企业微信配置显示客户主表、分配表、到店表三张独立连接卡，保留现有中继/直连模式，连接卡展示解析后的名称、表/视图标识、字段映射数量、最近校验结果和下一步操作。
3. 客户搜索列表将整行作为档案展开入口，操作列按钮阻止行事件冒泡；展开内容为数据库档案摘要和历史入口。
4. 可推广模板改为可搜索、可按线索类型/发布状态/范围筛选的列表；发布前可编辑 AI 原文、员工调整稿、模板标题、快捷码、线索类型和范围。
5. 账号与权限增加业务组模型及组长关系，列表分组展示；新增/编辑账号可选择业务组，组长角色只能在所属组中唯一。
6. 跟进规则搜索控件缩短，新增/编辑规则采用响应式分区表单；标签条件、规则元数据、动作分别布局，窄屏单列，不产生横向滚动。
7. 运营分析漏斗使用中文阶段名和逐层收窄的梯形/漏斗步骤，人数与转化率保留，宽度按容器自适应。

## 数据流与边界

- 页面继续通过 `AdminConsole.vue` 现有 API 客户端访问 `/admin/api/v1`。
- 前端新增的分组、模板范围和三表连接字段必须有后端 DTO/查询/保存接口；接口失败显示可恢复的错误和当前数据，不伪造成功状态。
- 既有接口字段保持向后兼容，旧模板没有范围时按全部成员显示，旧账号没有组时归入未分组。
- 仅允许管理员维护组和模板发布范围；组长可见自己的组，普通成员不获得额外管理权限。

## 验证标准

- Vitest 覆盖九个关键交互：测试入口、三表状态、客户整行展开、模板下拉与范围、分组账号、规则布局字段、中文漏斗。
- `npm run typecheck` 和现有 AdminConsole 测试通过。
- Impeccable detector 对改动的 Vue 文件无未解释的溢出、英文残留或固定宽度问题。
- 启动前端后，桌面宽度和 390px 窄屏下页面均可操作，不出现横向页面滚动。
