# 待办档案返回与模板发送确认设计

## 背景

当前从待办队列点击“档案”后会关闭待办抽屉并进入客户档案，但应用没有保存进入来源，因此无法返回原来的待办分类。左侧“模板”能够读取当前档案并替换客户变量，但复制动作只写入剪贴板，没有发送确认、跟进记录或待办完成处理。

系统现有“生成回复”和“批量模板”流程已经把发送确认接入 `/api/v1/chat/send-confirm`。本次让单客户模板流程与其共用同一后端契约，同时把“复制”和“实际发送”拆成两个明确动作，避免只复制未发送时误删待办。

## 最终用户流程

1. 用户从“今日待跟进”或其他待办分类点击客户“档案”。
2. 应用保存来源页面、待办抽屉状态和当前分类，然后打开客户档案。
3. 客户档案顶部显示返回按钮，可随时回到原来的待办分类。
4. 用户在客户档案中点击左侧“模板”。模板面板明确显示当前关联客户的昵称和脱敏手机号。
5. 用户点击某条文本模板的“复制”。系统只写入剪贴板，不记录跟进、不移除待办。
6. 当前模板卡片内把“复制”按钮替换为：
   - `已发送`
   - `未发送`
7. 点击“未发送”：清除本次待确认状态，客户继续保留在待办，模板面板保持打开，可选择其他模板。
8. 点击“已发送”：提交发送确认；成功后关闭模板面板、完成当前待办，并直接返回原来的待办分类继续处理下一位客户。
9. 关闭模板面板或应用时仍未确认：一律按“未发送”处理，不记录、不完成待办。

## 客户上下文

- 只有从当前可见的客户档案打开模板时，模板面板才关联该客户并显示“已发送 / 未发送”。
- 从工作台、全局快捷键或其他没有明确客户的入口打开模板时，只执行普通复制，并提示“未关联客户，本次不记录跟进”。
- 不允许使用客户档案 store 中残留的旧客户作为隐式上下文，避免把跟进记录写到上一个客户。
- 待确认期间其他模板的“复制”按钮暂时禁用；点击“未发送”后恢复，避免同时存在多个不明确的发送确认。

## 返回导航

- 应用在第一次从工作台或待办进入客户档案时保存一个单层返回上下文。
- 从待办进入：返回时恢复原桌面页面、重新打开待办抽屉并保持原分类。
- 从工作台客户卡进入：返回工作台，不打开待办抽屉。
- 客户档案加载完成后再次发出的 `customer:selected` 事件不得覆盖已保存的返回上下文。
- 模板“已发送”成功后复用同一个返回动作，不再让用户手动点击工作台并重新寻找客户。

## 发送确认与待办完成

模板“已发送”向现有 `/api/v1/chat/send-confirm` 提交：

- 当前客户完整手机号
- 昵称、客户类型、来源表
- 实际复制后的模板文本
- 模板标题和场景形成的跟进摘要/方向

后端收到确认后：

- 更新最近跟进时间。
- 写入可读的跟进记录，至少包含本次模板标题和实际发送文本，不允许产生空跟进记录。
- 如果生成了新的下次跟进建议，使用新的时间和方向替换当前待办。
- 如果没有新的下次跟进建议，清除已经完成的今日/逾期跟进时间和方向，使当前客户退出当前待办。
- 本地数据库与企业微信表格写入使用同一组跟进字段；表格暂不可用时进入现有写入队列，但本地待办完成不能依赖表格成功。

## 前端同步

- 发送确认成功后，待办 store 立即移除当前客户，避免返回列表时短暂看到旧任务。
- 客户档案触发现有刷新事件，更新最近跟进和跟进记录。
- 工作台标记为需要刷新；恢复工作台或达到刷新条件时重新读取后端数据。
- 后端最终数据与前端乐观状态不一致时，以后端为准，刷新后恢复真实状态并显示错误提示。

## 失败处理

- 剪贴板写入失败：不进入发送确认状态，显示“复制失败，请重试”。
- “已发送”接口失败：模板面板保持打开，客户不从待办移除，显示“跟进记录失败，请重试”。
- 重复点击“已发送”：第一次请求期间按钮进入忙碌状态，禁止重复提交。
- 用户点击“未发送”或关闭模板：不调用发送确认接口。
- 返回待办时如果原客户仍存在，保持后端真实结果；不根据复制动作自行隐藏。

## 测试范围

- App：从待办进入档案后可返回原分类；档案加载事件不覆盖返回上下文。
- Quick Search：有明确客户时复制后显示内联确认；无客户时只复制；未发送不调用后端；关闭不调用后端。
- Quick Search：已发送提交完整客户和模板字段；成功关闭并返回；失败保留面板和待办。
- Followup Store：确认成功只移除当前客户，不影响其他分类或选中状态。
- Backend：发送确认写入非空跟进记录；有下次建议时替换任务；无建议时完成并清除当前任务。
- Table Write：本地更新和外部表格字段一致；外部失败进入队列而不回滚本地完成状态。
- 回归：生成回复、批量模板、客户档案刷新、工作台统计、自动刷新和权限范围保持正常。

## 非目标

- 不尝试监听企业微信是否真正点击了“发送”，系统以用户点击“已发送”为唯一确认依据。
- 不新增多级浏览历史，只提供当前客户档案的一层返回。
- 不把没有明确客户上下文的全局模板复制记入任何客户档案。
