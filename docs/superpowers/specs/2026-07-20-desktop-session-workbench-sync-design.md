# Desktop Session And Workbench Sync Design

## Goal

让桌面端在公司电脑上长期运行时保持稳定登录和及时数据同步，同时减少重复入口和无意义状态提示，并允许管理员在正式后台调整关键参数。

## Confirmed Problems

- Access token 默认约 2 小时，refresh token 默认 7 天。
- refresh token 当前按用户名保存为单个 Redis 键；同一账号在桌面端和后台再次登录会互相覆盖，Redis 数据丢失也会导致续期失败。
- 工作台没有周期定时器，只在进入工作台、窗口聚焦、手动刷新或收到实时事件时更新。
- 工作台内部快捷入口与左侧固定入口重复。
- 左上角“未配置”表示 Skill 订阅到期日期缺失，但容易被误解为 Skill provider 未配置。
- 正式管理后台没有面向业务管理员的登录策略、工作台同步间隔和 Skill 到期日期设置表单。

## Session Design

- Access token 保持短周期，默认 2 小时。
- Refresh session 默认 30 天，并通过正式后台允许配置 1-30 天。
- Refresh session 改为数据库持久化，一次登录对应一个独立会话；桌面端和后台、不同设备之间互不覆盖。
- 数据库只保存 refresh token 的 SHA-256 摘要，不保存明文。
- 每次续期旋转 refresh token，旧 token 立即失效。
- 修改密码、停用账号、修改关键权限时继续撤销该账号全部 refresh sessions。
- 桌面端退出时尽力调用注销接口撤销当前 refresh session；即使接口失败也立即清除本地登录状态。

## Workbench Sync Design

- WebSocket 继续承担新客资、跟进提醒和公告的实时推送。
- 增加轮询兜底，默认每 60 秒检查并获取最新工作台数据。
- 正式后台允许设置 30-300 秒的工作台刷新间隔。
- 手动刷新、重新进入工作台和窗口重新聚焦继续保留。
- 连续失败三次后停止无休止自动请求，仍允许手动重试。
- 已加载数据在请求失败时保留，并显示“数据可能延迟”。

## Desktop UI Design

- 删除工作台内部“识别聊天 / 速搜模板 / 批量待办”重复区域，仅保留左侧固定入口。
- Skill 到期日期未配置时隐藏状态标签。
- 配置了日期时显示：`有效至 YYYY-MM-DD`、`即将到期 YYYY-MM-DD` 或 `已到期`。
- 工作台顶部保留同步时间和手动刷新按钮。

## Admin UI Design

在“账号与权限”页面增加“登录与桌面设置”面板：

- Access token 有效小时数，范围 1-24 小时。
- 免登录天数，范围 1-30 天，默认 30 天。
- 工作台自动同步秒数，范围 30-300 秒，默认 60 秒。
- Skill 到期日期，可留空。

保存继续复用 `/admin/api/v1/configs/{key}` 和现有配置刷新事件。

## Verification

- 后端：refresh session 多设备、旋转、过期、撤销、注销和配置范围测试。
- 桌面端：过期自动续期、退出注销、Skill 未配置隐藏、重复入口删除、周期刷新和失败停止测试。
- 管理后台：表单读取、保存、范围校验测试。
- 回归：后端定向测试、桌面完整测试、typecheck、build、renderer smoke、打包目录验证。

## Follow-up Priority Addendum

- 跟进分类按自然日判断：下次跟进日期早于今天才是“逾期跟进”，日期等于今天时全天保持“今日待跟进”，不因当天具体时刻已过而提前变成逾期。
- 待办队列四个入口顺序统一为：`今日待跟进`、`逾期跟进`、`今日预约`、`新客资`。
- 打开待办队列或从工作台进入待跟进时，优先打开“今日待跟进”；今日没有任务时再打开“逾期跟进”。
- 工作台今日跟进列表先展示今日待跟进，再展示逾期跟进；同类内部继续按原有时间和客户类型规则排序。
- 本地人工验收样例 `18800002222` 保留昵称“今日待跟进客户”，验收准备脚本每天把它的下次跟进时间刷新到当天晚些时候，避免固定日期跨天后污染测试结果。

## Task Queue Profile And Narrow Layout Addendum

- 待办队列的勾选框只用于批量选择；点击客户主要内容或“档案”按钮时，关闭待办队列并展示该客户档案，避免档案已经切换但仍被抽屉遮挡。
- 客户档案摘要区提供“复制客户昵称”图标按钮；成功后提示“客户昵称已复制，可到企业微信搜索”，昵称为空或复制失败时显示明确提示。
- 待办客户行保留整行可点击能力，同时增加可见的“档案”按钮，使用户不必猜测客户卡片是否可点击。
- 窄窗口批量栏采用两行布局：第一行显示已选数量、全选和反选，第二行使用整行主按钮“批量发模板”。所有操作文字保持完整，不在固定高度按钮内被截断。
- 420×760 默认窗口与 360×560 最小窗口都检查工作台、待办队列和客户档案中的可见按钮；任何按钮的内容宽度或高度超出自身边界均视为失败。
