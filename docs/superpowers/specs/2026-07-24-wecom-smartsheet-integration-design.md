# 企业微信智能表格连接设计

## 目标

把现有系统直接连接到企业微信官方智能表格接口，第一阶段只完成三项能力：

1. 查询“私域客资管理表”的记录。
2. 向“私域客资管理表”新增记录。
3. 按企业微信记录 ID 修改已有记录。

本阶段不删除记录，不修改表结构，不开发新的桌面页面，也不改动另一个会话正在开发的识图、回复任务、主管后台和模板功能。

## 已确认的目标表

| 项目 | 值 |
|---|---|
| 文档 ID | `s3_AY0AdQapAP8CN3A4oIQ1jT0SEgWNX` |
| 子表 ID | `tBXC1l` |
| 子表名称 | `私域客资管理表` |
| 视图 ID | `v86jaL` |
| 视图名称 | `总表` |

“总表”当前有 25 个显示列和 25 个隐藏列。查询使用该视图；新增和修改只允许写入该视图中可见、可编辑并且已经配置字段对应关系的列。

以下列只读，不允许写入：

- 所有公式列，包括 `是否到店（公式）`、`是否加微（公式）`、`是否转化（线索）`。
- 创建人、最后编辑人、创建时间、最后编辑时间、自动编号等系统列。
- “总表”中隐藏的列。
- 没有在系统中配置字段对应关系的列。

## 采用方案

系统后台直接调用企业微信官方接口，不再依赖现在代码中假设存在的“表格中转服务”。

使用的官方接口：

- 获取访问凭证：`/cgi-bin/gettoken`
- 查询字段：`/cgi-bin/wedoc/smartsheet/get_fields`
- 查询记录：`/cgi-bin/wedoc/smartsheet/get_records`
- 添加记录：`/cgi-bin/wedoc/smartsheet/add_records`
- 更新记录：`/cgi-bin/wedoc/smartsheet/update_records`

官方说明：

- [查询字段](https://developer.work.weixin.qq.com/document/path/101157)
- [查询记录](https://developer.work.weixin.qq.com/document/path/101158)
- [添加记录](https://developer.work.weixin.qq.com/document/path/99907)
- [更新记录](https://developer.work.weixin.qq.com/document/path/99909)

自建应用必须先被加入该智能表格的“可调用应用”列表。可信域名和可信 IP 已配置，但这两项不能代替智能表格自身的调用权限。

## 凭证和服务器配置

服务器通过环境变量保存以下配置：

- `WECOM_CORP_ID`
- `WECOM_APP_SECRET`
- `WECOM_SMARTSHEET_DOC_ID`
- `WECOM_SMARTSHEET_SHEET_ID`
- `WECOM_SMARTSHEET_VIEW_ID`
- `WECOM_SMARTSHEET_SOURCE_TABLE`
- `WECOM_SMARTSHEET_UNIQUE_FIELD_TITLE`，本表设置为 `联系方式`

真实 Secret 不进入代码、Git、数据库、日志、测试报告或聊天内容。应用的 AgentId 不参与本组智能表格接口鉴权，因此不作为必填配置。

访问凭证缓存在服务器内存中，并在企业微信返回的有效期前提前刷新。企业微信报告凭证失效时，只清除缓存并重新获取一次；仍然失败则停止本次操作并返回明确错误，不无限重试。

## 查询流程

```text
系统查询客户资料
  -> 使用 CorpID 和应用 Secret 获取访问凭证
  -> 查询“总表”的字段信息
  -> 分页查询“总表”记录
  -> 按字段类型把企业微信单元格转换为系统可读值
  -> 按现有字段对应关系写入本地客户资料缓存
```

查询记录使用字段标题作为 key，保留企业微信 `record_id` 作为系统的 `sourceRowId`，后续修改必须使用该 ID。

企业微信单页最多返回 1000 条，客户端按照返回的 `has_more` 和 `next` 继续分页。现有同步入口带有“修改时间”和“最多返回条数”，第一阶段会读取完整分页结果后按记录的 `update_time` 在本地筛选，确保不会因为只读第一页而漏掉修改记录。

值转换规则：

- 文本读取文本内容。
- 数字、勾选项、电话、邮箱直接转成对应基础值。
- 单选和多选读取选项文字，多个值使用稳定顺序合并。
- 日期按照企业微信的毫秒时间戳转换为 Asia/Shanghai 时区的日期或日期时间。
- 无法识别的复杂类型保留为安全的 JSON 文本，但不会自动写回。

## 新增和修改流程

```text
系统准备保存字段
  -> 使用现有字段对应关系得到智能表格列名
  -> 查询并缓存“总表”字段类型
  -> 忽略 null，保留用于清空字段的明确空字符串
  -> 拒绝公式列、系统列、隐藏列和未知列
  -> 按字段类型转换为企业微信要求的格式
  -> 调用添加记录或更新记录接口
  -> 检查 HTTP 状态和企业微信 errcode
  -> 保存返回的 record_id 或确认更新结果
```

写入使用字段 ID，而不是长期依赖可能被改名的列标题。每次字段缓存刷新时，通过可见列标题找到当前字段 ID；如果列被删除、重名、改成公式或被隐藏，保存操作失败并指出具体列名，不猜测目标列。

第一阶段支持系统当前会写入的类型：文本、电话、数字、勾选、日期、单选和多选。单选或多选必须匹配表中已经存在的选项，不自动创建新选项，避免写错选项污染表格。

新增记录前先用 `联系方式` 做完全一致查询：没有匹配记录才新增；只有一条匹配记录时直接返回该记录 ID；出现多条匹配记录时停止并提示人工确认。相同联系方式的并发新增在单个服务器进程内串行执行，避免两个同时到达的请求都通过新增前检查。

## 错误处理

所有企业微信响应同时检查 HTTP 状态和 JSON 中的 `errcode`。对外错误只说明发生在哪一步以及企业微信错误码，不返回 CorpID、Secret、访问凭证、完整请求体或客户隐私数据。

处理原则：

- 配置缺失：启动后第一次调用时立即失败并列出缺少的配置名。
- 没有表格调用权限：提示检查“可调用应用”，不误报为网络错误。
- 访问凭证失效：刷新一次后重试当前请求。
- 请求超时或企业微信暂时不可用：交给现有表格写入重试队列处理；新增重试必须再次执行 `联系方式` 完全一致查询。
- 字段不存在、被隐藏或变为只读：阻止写入，并指出字段名。

现有系统每次只新增或修改一条记录，不在本阶段扩大为批量写入。新增接口可能出现“企业微信已写入但本地没收到响应”的不确定情况，因此真实验收使用专用测试联系方式，并验证重试不会新增第二行。

## 与另一个会话的隔离边界

本功能只在工作树 `feat/wecom-smartsheet-integration` 中开发。

允许修改：

- `src/main/java/com/privateflow/modules/tablewrite/client/HttpWecomTableClient.java`
- 新增企业微信访问凭证、字段目录、值转换和官方接口客户端文件。
- 上述文件对应的后端测试。
- 本设计和后续实施计划。

禁止修改：

- `desktop/src/renderer/` 下的所有文件。
- `src/main/java/com/privateflow/modules/api/chat/` 下的所有文件。
- `ChatController.java`、`ConfigAdminService.java`、`SystemConfigRepository.java`。
- `pom.xml`。
- 所有数据库迁移文件。
- 另一个会话的识图、回复任务、主管后台、模板及其测试。

服务器在两个会话开发期间不替换运行程序。两个功能各自完成后，先合并代码、运行共同测试，再统一部署一次。

## 测试和验收

### 自动测试

- 访问凭证获取、缓存、提前刷新和失效后单次重试。
- 查询字段时只接受“总表”可见字段。
- 查询记录分页、更新时间筛选和各种单元格类型转换。
- 新增记录使用字段 ID 并返回 `record_id`。
- 相同联系方式的首次新增、重复请求和并发请求最多产生一行。
- 修改记录携带正确 `record_id`。
- 公式列、系统列、隐藏列、未知列和未知选项被拒绝。
- 企业微信非零 `errcode`、非 2xx、超时和无效 JSON 被正确处理。
- 日志和异常中不出现 Secret 或访问凭证。
- 现有客户查询、新增和修改服务测试继续通过。

### 真实企业微信验收

在服务器上使用专用测试记录，测试值必须带唯一标记且不能使用现有客户隐私数据：

1. 查询字段，确认文档 ID、子表 ID、视图 ID 和列类型正确。
2. 查询记录，确认可以读到专用测试记录。
3. 新增一条专用测试记录，确认智能表格出现且系统保存了返回的记录 ID。
4. 修改该测试记录的一个普通文本字段，确认原行被更新，没有新增重复行。
5. 尝试修改公式列，确认系统在请求发送前阻止。
6. 查询更新后的记录，确认读回值和写入值一致。

真实测试记录不自动删除，因为本阶段没有删除能力。验收完成后由用户在智能表格中手动删除测试行。

## 完成标准

只有同时满足以下条件，才能报告“企业微信智能表格已连通”：

- 自动测试全部通过。
- 原有表格相关测试全部通过。
- 服务器能够成功获取访问凭证。
- 对目标“私域客资管理表”的真实查询、新增和修改均成功。
- 公式列写入保护经过验证。
- 另一个会话的文件没有被修改。
- 尚未完成真实服务器验收时，只能报告“代码完成，等待真实连通验证”。
