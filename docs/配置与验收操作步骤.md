# 私域辅助系统配置与验收操作步骤

按顺序执行。每一步都要完成“操作 → 看到结果 → 刷新确认 → 记录证据”后，才能进入下一步。

## 第 0 步：准备材料

先准备好以下内容，不要边验收边找：

1. 最终访问域名和管理员初始账号。
2. 企业微信企业 ID、应用 Secret、回调 Token、EncodingAESKey，或服务器转发地址和转发密钥。
3. 客户主表、分配表、到店表的文档 ID、子表 ID、视图 ID、源表标识、唯一字段名称。
4. Skill、识图模型、LLM 的 Base URL、API Key、模型名和超时设置。
5. 一张脱敏聊天截图、一段文字聊天、一条测试客户手机号、一个测试门店和一个测试员工。
6. 最终桌面安装包及 SHA-256；临时测试账号：管理员、组长、员工各一个。

## 第 1 步：先修复并验收登录

1. 用浏览器打开最终域名根地址。
2. 必须看到系统登录页；如果看到 JSON、500、空白页，停止，先修复前端入口路由。
3. 用管理员账号登录。
4. 进入“系统健康监控”，确认数据库、缓存状态可以加载。
5. 刷新浏览器，确认仍在系统内。
6. 退出登录，再打开后台地址，必须回到登录页。
7. 用错误密码登录一次，必须明确提示失败。

**通过条件：**登录、刷新保持、退出失效、错误密码失败全部成立。否则后面步骤只做准备，不得算验收通过。

## 第 2 步：配置账号和权限

1. 打开“分析与系统 → 账号与权限”。
2. 保留管理员账号，修改初始密码。
3. 新增一个 `LEADER` 组长账号，填写显示名、手机号和所属组。
4. 新增一个 `KEEPER` 员工账号，填写显示名、手机号，并选择直属组长。
5. 分别退出管理员，登录组长和员工账号。
6. 检查三种账号能看到的菜单和客户范围是否不同。
7. 停用员工账号，退出后重新登录，必须失败。
8. 重置员工密码，确认旧密码失效、新密码可用。

## 第 3 步：配置企业微信连接

1. 登录管理员，打开“配置中心 → 配置中心”。
2. 没有固定公网 IP 时选择“服务器转发”。
3. 填写服务器转发地址（只填域名根地址，不加 `/wecom`）。
4. 点击“保存企业微信连接”。
5. 刷新页面，确认连接方式和地址仍在。
6. 如果选择“直接连接企业微信”，先把服务器出口 IP 加入指定应用的可信 IP，再填企业 ID 和应用 Secret。
7. 点击测试或保存，必须返回成功；失败时记录错误码，不要反复改表配置。

## 第 4 步：配置三张表和字段映射

依次配置，顺序不能调换：客户主表 → 分配表 → 到店表。

1. 打开“数据源与内容 → 客户数据对接”。
2. 新增客户主表数据源，填写名称、子表 ID、源表标识和说明。
3. 读取字段列表，确认唯一字段（通常是手机号）存在。
4. 保存手机号、姓名/昵称、客户阶段、来源、标签等字段映射。
5. 刷新页面，重新打开映射版本，确认刚才的映射仍在。
6. 对分配表重复 2～5 步，至少映射负责员工、组、门店、来源、分配状态。
7. 对到店表重复 2～5 步，至少映射预约日期、预约时间、门店、项目、到店状态和到店资料。
8. 点击每张表的“同步”，等待同步状态结束。
9. 用一个测试手机号在系统中查找，确认客户主表数据能显示。
10. 到企业微信对应表中按行 ID 回读，核对唯一手机号和写入字段。

**不通过时先检查：**页面选中的数据源 ID、数据库保存的数据源 ID、请求提交的数据源 ID是否一致；不要只看“有映射”三个字。

## 第 5 步：配置 Skill 场景（A）

1. 打开“配置中心 → Skill 场景管理”。
2. 新增一个场景绑定，选择场景、线索类型、Skill 环境和优先级。
3. 保存后刷新，确认绑定仍显示“当前可用”。
4. 点击“测试”，输入一段客户消息。
5. 确认页面同时显示 Skill 指导和最终回复话术。
6. 查看调用监控，确认产生一条调用记录。
7. 停用该绑定，再次测试，确认系统不会继续调用它。

## 第 6 步：配置 AI、识图、LLM 和降级（B）

1. 在“配置中心 → 配置中心”新增 Skill 环境，填 Base URL 和 API Key，测试并启用。
2. 新增识图模型环境，填 Base URL 和 API Key，测试并启用。
3. 新增 LLM 环境，填 Base URL、API Key、模型名、协议、超时和最大 Token，测试并启用。
4. 为以下五个场景各配置一条路由：回复生成、档案提取、跟进建议、异常识别、总结补位。
5. 确认每条路由都有优先级和启用状态。
6. 填写企业红线和降级回复，保存后刷新确认。
7. 用错误 API Key 做一次连接测试，确认页面显示失败原因。
8. 暂停主模型，执行一次回复生成，确认出现重试或降级回复，不会自动发送消息。

## 第 7 步：配置速搜内容（D）

1. 打开“数据源与内容 → 速搜内容管理”。
2. 新增普通开场话术、团购话术、到店提醒、知识片段、门店定位、小程序引导各一条。
3. 每条填写标题、快捷码、内容、线索类型和启用状态。
4. 保存后刷新，确认内容仍在。
5. 在桌面端打开速搜，分别搜索标题和快捷码。
6. 复制一条内容，确认剪贴板内容准确。
7. 使用重复快捷码、空内容各测试一次，确认系统拒绝并提示原因。

## 第 8 步：配置可推广模板（D1）

1. 员工在桌面端保存一份调整后的回复模板。
2. 管理员打开“数据源与内容 → 可推广模板”。
3. 找到该员工候选模板，选择发布范围：全员或指定组。
4. 用目标员工账号登录，确认能看到模板。
5. 用非目标组账号登录，确认看不到模板。
6. 撤回模板，刷新员工端确认模板消失。

## 第 9 步：配置跟进规则（F）

1. 打开“组织与规则 → 跟进规则引擎配置”。
2. 新增一条逾期提醒规则，设置条件、提醒动作和生效状态。
3. 新增一条需要通知组长的规则。
4. 用测试客户制造满足条件的数据。
5. 打开员工工作台，确认生成跟进任务。
6. 打开组长账号，确认收到授权范围内的通知。
7. 停用规则，再次制造条件，确认不再生成新任务。

## 第 10 步：配置标签和客户分层（G）

1. 打开“组织与规则 → 客户标签与分层”。
2. 新增一个单选分类和两个值。
3. 新增一个多选分类和两个值。
4. 给测试客户分别选择标签，刷新客户档案确认标签仍在。
5. 执行一次合并预览，确认旧值、新值和影响客户清单正确。
6. 确认合并后旧值只能作为历史映射，不能再被新数据误写。
7. 导出标签分类，打开文件核对数量和名称。
8. 测试重复值、停用值、跨分类值，确认均被拒绝。

## 第 11 步：验收唯一事实数据库（C1）

1. 打开“数据源与内容 → 唯一事实数据库”。
2. 用完整手机号查找测试客户。
3. 查看全部字段、当前真实值、字段历史。
4. 修改客户资料后刷新，确认值仍在且历史增加一条。
5. 用只有昵称的条件查找，确认系统不会直接正式匹配客户。
6. 测试手机号冲突，确认系统提示人工确认而不是覆盖原客户。

## 第 12 步：验收分析与监督（H、I）

1. 先完成至少一次识别、一次回复复制、一次跟进、一次预约和一次到店资料保存。
2. 打开“分析与系统 → 运营分析看板”。
3. 查看使用量、转化漏斗、员工效能、客户来源、阶段、健康、生命周期、风险和内容排行。
4. 修改日期和员工筛选，确认数字随筛选变化。
5. 导出当前看板，打开导出文件，确认与页面筛选一致。
6. 打开“主管监督记录”，按员工、渠道、来源筛选。
7. 从一条指标追到原始客户或任务，确认能解释数字来源。
8. 用员工账号访问，确认不能越权查看其他组数据。

## 第 13 步：配置治理、公告、版本和审计（J、K、L、M）

1. 在“数据保留与任务设置”填写监督记录、技术日志和任务队列留存时间，保存并刷新确认。
2. 输入负数或过小容量，确认保存被拒绝。
3. 在“系统公告”发布一条立即公告，确认员工端显示。
4. 再建一条定时公告，确认到时间后显示。
5. 停止公告，刷新员工端确认消失。
6. 在“版本管理”上传安装包，核对版本号和 SHA-256。
7. 发布一个测试版本，再撤回；确认撤回版本不可继续下载。
8. 打开“操作审计日志”，查找刚才的账号、映射、公告和版本操作。
9. 查看详情并导出 CSV，确认密码、Token、API Key 已脱敏。

## 第 14 步：桌面端主流程

1. 安装最终桌面包，确认它使用服务器域名，不是 `localhost`。
2. 用员工账号登录工作台。
3. 切到微信客户聊天窗口，点击“识别聊天”。
4. 确认任务状态从排队、识别到生成；失败时确认有明确原因和重试按钮。
5. 识别出客户后，选择正确客户档案；只识别出昵称时不得直接归档。
6. 查看三条回复建议，复制一条；确认系统没有自动发送。
7. 点击“预约”，填写日期、时间、项目和门店，提交并复制预约话术。
8. 确认预约事实已保存到唯一事实数据库，到店表出现对应待同步任务。
9. 打开“待补充到店资料”，填写资料并上传图片或 PDF。
10. 确认资料保存、文件可再次打开，到店表按行 ID 回读成功。
11. 断网后执行一次允许的本地操作，恢复网络，确认队列只同步一次。
12. 用 5 个员工账号并发识别，确认任务和结果互不串号。

## 第 15 步：最终放行检查

只有下面全部打勾，才可以写“验收通过”：

- [ ] 登录、刷新、退出、错误密码全部通过。
- [ ] ADMIN、LEADER、KEEPER 权限边界全部通过。
- [ ] 客户主表、分配表、到店表分别完成映射、同步和行回读。
- [ ] Skill、识图、LLM 使用真实配置，`MOCK_EXTERNALS=false`。
- [ ] A～N 每个板块都有操作截图和结果记录。
- [ ] 桌面端识别、客户确认、回复、预约、到店资料全部通过。
- [ ] 至少一条“桌面端 → API → 数据库/队列 → 企业微信表回读”链路通过。
- [ ] 备份和恢复演练通过。
- [ ] 安装包签名、发布、下载和撤回通过。
- [ ] 没有未解释的阻塞项或“只展示未落库”项。

任何一项未完成，最终结论写：**未通过，阻塞项为：……**，不要写“基本完成”。
