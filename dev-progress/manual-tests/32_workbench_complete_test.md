## 1. 当前版本真实口径

- 工作台只有三张指标卡：`待跟进`、`今日预约`、`新客资`。
- `待跟进` = `逾期` + `今日待跟进`，当前没有单独的“逾期数量卡”。
- 待办队列内四个分类卡顺序为：`今日待跟进`、`逾期跟进`、`今日预约`、`新客资`，默认先打开今日待跟进。
- 下次跟进日期等于今天时全天归入“今日待跟进”；只有日期早于今天才归入“逾期跟进”。
- 每张指标卡显示总数，以及其中的`团购`、`线索`数量；`待确认`只计入总数。
- 当前没有“公告数量卡”和“健康状态卡”。公告以内容条展示，健康状态属于提醒中心/系统健康模块。
- 今日跟进默认最多显示 5 条，新客资最多显示 3 条，公告最多显示 3 条。
- 默认自动刷新间隔为 60 秒，可在管理后台设置为 30-300 秒；手动刷新可立即请求最新数据。
- 本模块不依赖企业微信表格写入，可以在本地先完成测试。

## 2. 测试分工

- `[人工]`：用户在桌面应用中操作并描述看到的结果。
- `[Codex]`：Codex 准备测试数据、控制接口成功/失败、检查数据库/API/日志和权限范围。
- `[共同]`：Codex准备场景，用户观察应用端，失败后由 Codex 定位并修复。

用户不需要自行检查后端，也不需要自行制造断网、公告、逾期客户或多角色账号。
