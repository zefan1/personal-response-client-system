# 私域辅助系统最终人工测试 Tasklist

> 创建日期：2026-07-20  
> 适用版本：当前工作区 `backup/2026-07-20-full-state` 及其后续修复版本  
> 测试目标：按模块逐项人工验证，发现问题后暂停当前模块、记录问题、修复并回归，再进入下一个模块。

## 0. 测试规则

### 0.1 当前测试环境

- 后端：`http://localhost:8080`
- 前端/Vite：`http://localhost:5173`
- 数据库：`private_domain_assistant_smoke`
- 管理员：`admin/admin123`
- 浏览器或桌面端 API 地址：使用 `http://localhost:8080`，不要优先使用 `127.0.0.1`
- 当前真实 provider：LLM、Skill、图像识别已经配置；企微表格仍需单独验收

### 0.2 数据规则

- 现有样例客户只读：`18800001111`、`18800002222`、`18800003333`、`13900000001`
- 所有新增账号、规则、标签、模板、数据源、版本使用统一前缀：`FT20260720-模块编号-测试内容`
- 测试结束后删除或停用本模块创建的数据；不能删除已有业务数据
- 涉及真实 provider 时只使用脱敏聊天文本、脱敏截图和测试表
- 不在截图、日志、问题描述中记录 API key、JWT、完整手机号或客户隐私

### 0.3 结果标记

- `[ ]` 未测试
- `[x]` 通过
- `[!]` 有问题，已经记录问题编号
- `[B]` 阻塞，需要配置、样本或用户决策
- `[-]` 明确跳过，并填写原因

### 0.4 每个模块的固定记录

每完成一个模块，都填写：

- 开始时间、结束时间
- 测试人
- 结果：通过/有问题/阻塞/跳过
- 问题编号
- 截图或录屏路径
- 相关接口、请求时间和日志时间
- 清理结果

### 0.5 失败处理规则

1. 先不要继续下一个功能，保留当前页面和数据现场。
2. 记录问题编号，例如 `FT-P001`。
3. 记录“操作、实际结果、预期结果、复现次数、截图、时间”。
4. 让 Codex 修复后，先重测失败项，再重测当前模块，最后重测受影响的相关模块。
5. 修复未回归前，当前模块不能标记为通过。
